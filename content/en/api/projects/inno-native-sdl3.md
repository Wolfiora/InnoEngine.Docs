# Inno.Native.Sdl3

This project contains the SDL3 bindings generated by BindGen-CS and the small handwritten initializer that selects the deployed module. Application features normally use [the SDL3 platform backend](../../backends/sdl3.md) through neutral platform interfaces. Raw SDL types and addresses belong inside the Native and adapter boundary.

## Choose the supported integration

`Inno.Adapter.Platform.Sdl3` owns the engine's window and event integration. SDL3 toolchain code owns preparation, and Native tests exercise the selected deployment. The binding project does not become a second platform service or expose raw pointers to scripts.

The generated declarations include functions, structures, flags, callbacks and pointer wrappers. Handwritten duplicates of generated platform structures are not another supported API. `SDL.cs` selects the module; `Generated/Bindings.cs` defines the actual ABI.

## Shared ABI contract

The reference describes the checked-in HostSource binding, whose generated header identifies `windows-x64-msvc`, evaluated as a Debug CLR source surface. This is not proof that its layout or every symbol works on another target. A product's integration must select the matching ABI profile, generated managed declarations, native payload and runtime together.

Raw pointers and callback addresses do not carry managed ownership. Keep their owning module, resource, buffer and callback registration alive for the complete borrowing interval. A signature alone does not specify buffer capacity, encoding, nullability, a thread guarantee or ownership transfer. Use the member's upstream/XML contract and the consuming backend's explicit lifetime protocol. Where the generator has no safe semantics, the declaration remains a raw ABI call; documentation does not invent a safe wrapper.

The shared `SDL` facade owns one explicitly installed binding context. Replacing it closes the previous context; existing BGCS resource leases retain the previous context's native cleanup capability. A copied native address does not acquire such a lease. Do not close or replace a context while an unprotected consumer can still call through it.

The engine adapter imposes its own owner-thread and resource-order requirements. An upstream function documented as usable from any thread does not make an entire platform window, input session or callback lifecycle thread-safe. Read the [backend's ownership and thread boundaries](../../backends/sdl3.md) before integrating the raw API.

## Dynamic and static products

The handwritten initializer selects one of three declared paths: runtime imports, static linkage, or an explicitly deployed dynamic library. Dynamic Debug and Release configurations use their corresponding logical SDL3 module identities. Dynamic path resolution reads the product deployment index, then the generated loader establishes the function table.

Browser integration supplies its explicit wasm32 ABI, managed runtime and static library name. Windows and macOS integrations supply their own profiles. The component maintains common binding configuration rather than an independent platform-selection table. Static products use `INNO_STATIC_NATIVE` and do not initialize the dynamic loader.

HostSource output belongs to the component's `Generated/Bindings.cs` and `Native/Generated` locations. TargetArtifacts managed and native outputs belong to the same target/fingerprint generation. Never combine declarations from one generation with a library selected from another cache entry.

## Selected exports and failure

The common binding roots exclude `SDL_assert.h`: the engine does not consume the assertion API or the compiler builtins declared by that header. This is a component semantic boundary across targets, not a hand-maintained operating-system symbol blacklist.

Dynamic function-table initialization requires every selected export. Missing declarations, an incomplete deployment or an incompatible library are failures; another module is not silently substituted. Native initialization/call tests verify this separately from source declaration comparison.

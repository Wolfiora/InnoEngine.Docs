# Inno.Native.MiniAudio

This project exposes the generated miniaudio C ABI: function tables, `Ma*` enums, structures, delegates and pointer wrappers. It is a backend implementation surface, not the stable gameplay audio API. Use [Inno.Audio](inno-audio.md) from gameplay and the MiniAudio adapter from host composition.

## ABI and deployment contract

The binding is generated by the selected BGCS tool and component configuration from the pinned `extern/miniaudio/miniaudio.h`. Managed declarations and the native library must come from the same header/source revision. The inspected header is miniaudio 0.11.25. Upgrading replaces the selected ABI rather than retaining an implicit old ABI compatibility path.

Target profiles are build inputs, not runtime toggles. Dynamic products load from their deployed `native` closure using the product deployment index. Debug and Release select the corresponding `miniaudio-debug` or `miniaudio-release` logical library; the loader does not guess platform prefixes or extensions.

The first generated function call loads the required function table. Missing required exports fail immediately, even when the intended call would not otherwise use that export. Do not mix a newer generated table with an older installed library.

The handwritten initializer selects runtime imports, static linkage or the explicitly deployed dynamic module. The shared facade installs one generated binding context. Replacing or closing it ends that context's ordinary use; existing BGCS resource leases can retain its native cleanup capability. Copying a raw address does not acquire a lease. Do not replace a context while unprotected consumers can still call it.

The checked-in HostSource binding identifies `windows-x64-msvc`. The reference capture is a Debug CLR source surface, not a certificate of layout or execution on another target. Product integration must select matching generated declarations, native payload and runtime for its actual ABI.

## Native lifetime contract

Configuration initializers return value data. Any pointed-to bytes, callbacks or user data still require caller-owned lifetimes. Allocate ABI-compatible structure storage, call the matching initialization function and check its exact `MaResult` success value before recording initialization. The current generated success member is `MaResult.MA_SUCCESS`.

Only successfully initialized objects receive the corresponding uninitialization call. Stop voices, finish source access and drain processing/preparation before uninitializing their engine/device and freeing structure memory. A pointer wrapper does not copy its target, prolong its lifetime or call Uninit automatically.

Callbacks may run on an audio-processing thread. They must not access Editor or scene owner-thread state directly, throw exceptions across the native boundary or outlive retained callback/user-data storage. Do not carry native pointers, delegates or plugin runtime objects across a retired generation.

The adapter allocates separate engine storage, tracks successful initialization and explicitly supplies a processing buffer in hardwareless mode. Those are adapter guarantees, not automatic behavior supplied by every raw ABI call. Raw native APIs do not own InnoEngine assets, identities or scene lifetimes.

## Inspect the deployed library version

This host-only unsafe helper requires an already prepared matching native deployment. It is appropriate for a native test or backend diagnostic; it does not replace product-closure validation.

```csharp
using System.Runtime.InteropServices;
using Inno.Native.MiniAudio;

public static class NativeAudioVersion
{
    public static unsafe string? Read()
    {
        uint major = 0;
        uint minor = 0;
        uint revision = 0;
        MiniAudio.Raw.Version(&major, &minor, &revision);
        return Marshal.PtrToStringUTF8((nint)MiniAudio.Raw.VersionString());
    }
}
```

## Static products and generated ownership

The component keeps one shared binding definition. Platform integrations supply their actual ABI, runtime and static-library selections. Static products use `INNO_STATIC_NATIVE` and do not initialize a dynamic loader. The browser integration supplies wasm32 inputs; desktop integrations supply their own profiles. Target presence is not proof of completed runtime acceptance, and Linux is not claimed as a current distribution target.

Host-source generated outputs stay with the component's `Generated/Bindings.cs` and `Native/Generated` owners. Target-artifact managed/native outputs belong together under the selected binding generation. Consumers retain reading protection until linking or deployment finishes.

## API reference

Generated members associate explicitly with the shared ABI/lifetime contract above. Exact source declarations are retained, including pointer signatures and overloads. Many upstream generated members have no member-specific XML; common ABI constraints do not establish complete behavioral prose for every function. Consult the pinned upstream header when implementing a raw operation and keep unverified source/runtime status explicit.

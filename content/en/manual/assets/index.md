# Assets, importing and deployment content

An asset has a persistent identity, a canonical value and potentially loaded resources. Its source file, import metadata and generated artifact are related inputs and outputs, not interchangeable copies of the asset.

## Authoring and runtime

The authoring pipeline discovers sources, imports them and prepares content-addressed outputs. Runtime asset services read a validated deployment store and do not invoke source importers. Editor last-good content can remain useful after an import failure, but that failure cannot certify a new Player build.

For the underlying model, read [asset publication and recovery](../../architecture/asset-publication.md). To add a format, read [writing an importer](../../extending/asset-importers.md). Exact host contracts live in the [Assets](../../architecture/projects/inno-assets.md), [Assets Pipeline](../../architecture/projects/inno-assets-pipeline.md) and [Content](../../architecture/projects/inno-content.md) references.

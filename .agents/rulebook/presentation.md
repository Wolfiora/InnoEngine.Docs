# Presentation requirements

Use Astro/Starlight with readable Markdown content loaded directly from `content/en/`. The website is a presentation of the canonical content, not a separate source of API facts.

## Reading experience

Provide hierarchical navigation, a comfortable main column, an in-page contents list, visible search, light/dark themes, and responsive navigation. Use the InnoEngine logo with its author credit and separate license. Do not copy Godot branding or invent another logo source.

Derive one navigation tree from canonical categories and authored navigation. Publish content-addressed child lists as shared static resources; each page renders only root entries. Load children on expansion and preserve reader choices. Every top-level group is disclosure-only with a chevron; its label does not navigate. At every depth, disclosure-only groups use chevrons. Only inside API Reference below the root may a registered group home use square plus/minus controls and a linked label. All non-API groups are disclosure-only chevrons by code policy. Retained landing-page children must have distinct explanatory labels, never duplicate the parent name. Both expansion and collapse animate, respecting reduced-motion preferences. Center controls against the complete label row, including wrapped labels. Highlight the current page and its ancestor rows with a translucent background and bold label. Use a visibly lighter ancestor background than the selected row. An API member selects its registered declaring type. Hide methods, properties, constructors, fields and events from the sidebar; a type only expands when it has nested types. Derive nested ownership from captured declarations. Keep the complete page relationships for pagination, independently of sidebar visibility. An unrelated expanded branch has its child tree line color at 50% opacity normally and the full tree line color on hover, with normal-weight text and no underline. Underline only the current page label; ancestors are not underlined. The current page has a stronger background than its ancestors, including on hover; hover alone must not change text weight. Leave vertical space between row highlights and equal horizontal clearance from the left tree line and the right content/scrollbar edge. On desktop, animate the left sidebar's width to fit visible unwrapped labels up to one third of the viewport, then scroll horizontally without wrapping labels; allow the right TOC to resize while retaining readable body space, fill that body column with Markdown using only its normal side padding (no fixed maximum width or automatic left margin), and use the full-width mobile menu. Build restored descendants before revealing their branch so asynchronous loading cannot interrupt the opening layout. Preserve authored non-API navigation and pagination order. Only API siblings sort expandable groups before leaves, alphabetically within those two categories; use that same order for API pagination. Member pagination follows the canonical Members table exactly, including kind grouping. Settled expanded branches use natural block height rather than fractional grid tracks. Do not abbreviate sidebar labels or provide a compact-mode toggle. No-JavaScript readers retain ordinary category tables and essential content. Validate shared navigation once and each page's own HTML, declarations, links and anchors.

API pages show a compact icon and editorial status at the right end of the main context header, left of the TOC divider. Right-align and vertically center it. Fade its bounded status region from the status color on the right to background on the left. TABLE OF CONTENTS starts at the top of the right column. Behind it, render an oversized original logo SVG with its unmodified fills, clipped at the panel edges; its left edge aligns with the heading text center. Interpolate opacity from 0.2 at minimum TOC width to 0.8 at half-viewport width. Decoration must not intercept input or enter the accessibility tree. Non-API pages have no editorial status. The desktop divider supports pointer and keyboard resizing: default at three quarters of viewport width, minimum right width fits its unwrapped heading, maximum right width is half the viewport. Render the divider as one 5px neutral gray bar with a wider pointer target. Anchor the bar to the actual right column and replace the framework border when the control is available; only one divider is painted. Indicate hover and keyboard focus by changing the bar shade, without the global full-height focus outline. Mouse focus must not retain keyboard focus paint after dragging; preserve normal keyboard focus feedback and clear drag state on cancellation or window blur. Preserve the session choice, support double-click reset and re-clamp on viewport changes. Narrow screens retain the status in the context header and use the mobile TOC without a resize control. Do not show the old body panel or its description. Put the actual source summary directly below the title in a Markdown blockquote. Render one bullet per summary inside that quote, including a single summary; keep multiple paragraphs in one summary together. Use a subtle neutral background only for API summary quotes, equal vertical padding and bullets aligned with the required-contract list. Keep the responsive status visible without JavaScript. The source XML summary is the default. An editable nullable description list overrides the introduction and all type/member/category table descriptions consistently in website and queries; it is not stored in the editable body. Generate remarks, parameters, returns, exceptions and examples as readable Markdown sections, at the same heading level as Declaration. Named-author ownership can replace body sections; description overrides replace summaries, never declarations. Preserve manually owned prose. Use the existing editorial states: pale yellow Synced for XML-managed prose, pale red Outdated for manual prose with changed contracts or requested review, and pale green Verified for manual prose without pending review. Verified is not a machine guarantee of semantic correctness. Separate generated and author-editable API frontmatter with YAML comments and a blank line. Preserve authored body bytes when updating metadata; omit body editing links and target/configuration dumps. Put each API metadata field on its own line, sorted alphabetically by label, in one compact paragraph separated by hard line breaks before Declaration. Put source provenance directly above the footer's GitHub editing link. Preserve applicability facts in canonical references and query provenance.

Keep keyboard focus visible. Use semantic headings, meaningful accessible names, and sufficient contrast. Ordinary prose must not overflow horizontally. Signatures, code, and data tables may scroll inside their own containers. Necessary information must remain available without client JavaScript.

Theme components own layout. Ordinary content does not import MDX components or execute scripts. Important constraints must remain visible without expanding a disclosure. Supported Markdown must agree between the canonical parser, GitHub reading, and rendered anchors.

## Verification

Reveal and select the current page's sidebar path on every page load, including search results, body links, refreshes and direct URLs. Current ancestors override remembered closed state; unrelated disclosure choices remain intact. Derive secondary-page and type entries from canonical routes and registered containment; member URLs select the owning type. Embed only the current ancestor keys per page, retaining shared lazy navigation resources. The home and error pages have no artificial selected entry.

On desktop, align the header search control with the actual Markdown column, including its side padding, and track left navigation and right TOC resizing. Keep the compact header usable on narrow screens. All Markdown tables fill the body column with left-aligned cells. Keep leading columns at their natural content widths when space permits and put surplus width in the last column. Each column's minimum is its unwrapped heading plus cell padding. When space is insufficient, reduce the widest columns that remain above their minimum first, and wrap long body identifiers. Use fractional scrollport measurements and pixel column widths without percentage/integer feedback. Keep natural-width columns stable during continuous resizing and update sizes before painting; show a horizontal scrollbar only when the sum of heading minimums exceeds the available width, never transiently during resizing when they still fit. Preserve semantic tables and a usable layout without JavaScript.

Inspect landing, manual, tutorial, API, search, and error states in both themes at desktop, tablet, and mobile widths. Verify deep links under the documentation base path on the selected host, keyboard navigation, copy controls, and code/table overflow. A successful static build alone is not visual or accessibility acceptance.

Use sibling-only Previous/Next links for every registered page. Never cross parents or move into children; API members stay within their declaring type. Singleton groups have no pagination. Every page footer includes copyright, website creator FLwolfy and either XML-generation attribution or the named prose author, without framework credits.
